# Anti-Slop Audit Report: audit-002-2026-10-06

**Audited Target**: Blackboarder Web Dashboard (`mobile-web/`)  
**Audit Scope**: Visual Styling, Color Contrast (WCAG AA), Theme Parity (Light vs Dark), Responsive Layout, Scrollbar Alignment, and Icon Spacing.  
**Mode**: Mode 2 (Post-Implementation Audit)

---

## Executive Summary

A comprehensive visual and technical audit of the live website was conducted using Chrome DevTools across multiple viewports (Mobile 390px, Desktop 1200px) and both Light and Dark themes.

Overall, the layout, typography, calendar alignment, and modal drawers are responsive and structurally sound. However, the audit identified **4 high-priority contrast issues in Dark Mode** (where buttons and course labels fail WCAG AA contrast standards or render white-on-white), along with **3 layout and styling polish items**.

Per Mode 2 rules, all findings are catalogued below with their governing rules, priority tiers, and one-line reasons. **No files have been modified yet.** Please review and approve which numbered findings you would like fixed.

---

## Numbered Findings List

### Finding 1: Invisible "Save" Buttons in Modals (Dark Mode)
- **Rule**: `R-25` (Color Contrast — WCAG AA) & `R-34` (Every Theme You Ship Must Work)
- **Priority**: `HIGH` (Hard Gate)
- **Location**: `mobile-web/styles.css:2972` (`.btn-save-action`)
- **Reason**: In dark mode, `--primary` is `#f4f4f6` (near-white) while `.btn-save-action` sets `color: #fff`, rendering white text on a near-white background (1.10:1 contrast ratio, failing WCAG AA).
- **Affected Elements**: "Save Changes" (Edit Deadline modal) and "Save Deadline" (Add Custom Deadline modal).
- **Recommended Action**: Add `[data-theme="dark"] .btn-save-action { color: #111114; }` with a consistent dark hover state.

---

### Finding 2: Invisible "Open" Buttons in Quick Links Manager (Dark Mode)
- **Rule**: `R-25` (Color Contrast — WCAG AA) & `R-34` (Every Theme You Ship Must Work)
- **Priority**: `HIGH` (Hard Gate)
- **Location**: `mobile-web/styles.css:3641` (`.btn-ql-open`)
- **Reason**: In dark mode, `--primary` is `#f4f4f6` while `.btn-ql-open` sets `color: #ffffff`, producing white text on a near-white background (1.10:1 contrast ratio).
- **Affected Elements**: "Open ↗" buttons on every link card inside the Academic Quick Links modal.
- **Recommended Action**: Add `[data-theme="dark"] .btn-ql-open { color: #111114; }` with a consistent dark hover state.

---

### Finding 3: Low Contrast on Task Card "Edit" Action (Dark Mode)
- **Rule**: `R-25` (Color Contrast — WCAG AA) & `R-34` (Every Theme You Ship Must Work)
- **Priority**: `HIGH` (Hard Gate)
- **Location**: `mobile-web/styles.css:2819` (`.btn-card-action.btn-card-edit`)
- **Reason**: `.btn-card-action.btn-card-edit` overrides theme variables with hardcoded `color: #475569`, yielding a 2.34:1 contrast ratio on dark `#18181b` card surfaces (fails WCAG AA 4.5:1), and its hover state flashes an un-themed white `#f1f5f9` background.
- **Affected Elements**: The "Edit" button at the bottom of all deadline cards in the Deadlines tab and Day Sheet drawer.
- **Recommended Action**: Provide `[data-theme="dark"] .btn-card-action.btn-card-edit { color: var(--text-main); }` with dark hover background `#2c2c34`.

---

### Finding 4: Low Contrast on Inline Day Summary Course Names (Dark Mode)
- **Rule**: `R-25` (Color Contrast — WCAG AA)
- **Priority**: `HIGH` (Hard Gate)
- **Location**: `mobile-web/app.js:2982`, `mobile-web/styles.css:1486` (`.selected-day-course`)
- **Reason**: Course names in the inline day list receive raw subject colors via inline style (e.g. `#525252` for English, `#7c7c7c` for Computer Eng), which on dark card background `#18181b` yields a 2.27:1 contrast ratio (failing WCAG AA).
- **Affected Elements**: The course name header on items in the "Deadlines for [Date]" section below the calendar.
- **Recommended Action**: In dark mode, ensure `.selected-day-course` renders in high-contrast `#f8fafc` while keeping the card's colored left border to distinguish the course (matching how Deadlines tab handles course badges).

---

### Finding 5: Missing `.mr-1` Spacing on Embedded SVG Icons
- **Rule**: `R-05` (Layout & Spacing Rhythm) & `R-20` (Visual Identity & Polish)
- **Priority**: `LOW` (Quality Locks)
- **Location**: `mobile-web/styles.css`, `mobile-web/index.html:332,337,341,362`, `mobile-web/app.js:2971,2985,2986`
- **Reason**: The utility class `.mr-1` is used across many SVG icons (calendar title, add button, details button, quick links bar, clocks, pins, scales), but is undefined in `styles.css`, causing icons to touch text with 0px spacing.
- **Affected Elements**: Header labels like `Deadlines for [Date]`, buttons, and metadata pills.
- **Recommended Action**: Add `.mr-1 { margin-right: 5px; }` in `mobile-web/styles.css`.

---

### Finding 6: Unstyled Horizontal Scrollbar on Course Legend
- **Rule**: `R-05` (Consistency in UI Patterns)
- **Priority**: `LOW` (Quality Locks)
- **Location**: `mobile-web/styles.css:718`
- **Reason**: CSS targets `.course-legend-bar::-webkit-scrollbar`, but the actual DOM container is `.legend-items`, causing the Registered Courses scrollbar to display a default bulky browser scrollbar instead of the sleek customized track and thumb.
- **Affected Elements**: The "Registered Courses" scrollable chip bar under the calendar.
- **Recommended Action**: Update the selector to `.legend-items::-webkit-scrollbar, .quick-links-chips-row::-webkit-scrollbar`.

---

### Finding 7: Grade Progress Badge Displaying Confusing ">100%" Value
- **Rule**: `R-17` (Data & Numbers — Accuracy)
- **Priority**: `HIGH` (Hard Gate)
- **Location**: `mobile-web/app.js:3732`
- **Reason**: The progress badge in the Syllabus Grade widget displays `46% Done (145% completed)` because it sums raw percentages across all 6 courses instead of indicating total points or an average.
- **Affected Elements**: The progress badge on the Syllabus Grade Progress card in the Deadlines tab.
- **Recommended Action**: Format the secondary metric as total points e.g. `${overallPct}% Done (${Math.round(totalTrackedCompleted)} pts)` or remove the confusing secondary percent.
